## Ветки
- `main` защищена: изменения только через pull request.
- Ветка задачи создается от актуального `main` и называется `<тип>/issue-<номер>-<кратко>`,
  например `docs/issue-12-reproducible-setup`.
- Типы: `feat`, `fix`, `docs`, `chore`, `ci`, `test`.

## Commit
- Формат: `<тип>: <что сделано>`, например `docs: document reproducible setup`.
- В commit попадают только файлы, относящиеся к задаче. Перед commit: `git status` и `git diff`.
- Нельзя коммитить секреты, `.env`, `.venv`, кэши, модели и данные.

## Issue
- Каждая задача оформляется issue по шаблону с наблюдаемым результатом и критериями приемки.

## Pull request
- PR ссылается на issue (`Closes #N`), описывает результат и способ проверки.
- Автор назначает reviewer из команды. Автор не одобряет собственный PR.
- Для merge нужны: минимум одно одобрение другого участника, успешный CI (`quality`),
  разрешенные обсуждения.

## Review
- Reviewer воспроизводит команды или проверяет CI run, просматривает весь diff,
  оставляет конкретный комментарий.
- После новых commit одобрение проверяется заново.
